# 多 Agent 小说创作助手设计文档计划

## 修改目标

把已确认的多 Agent 小说创作助手方案整理为可供后续实施使用的正式设计文档，明确都市校园与科幻未来两类小说的设定共创、1500–3000 字正文生成、审校、人工确认、长期记忆和外部 Skill 安全隔离边界。

## 修改范围与明确不包含的内容

### 修改范围

- 记录主编 Agent、专业 Agent 与代码编排器的职责边界。
- 记录背景与人物丰富、章节正文生成和小说圣经的数据流。
- 定义字数、连贯性、重复表达和“AI 味”质量门禁。
- 定义失败恢复、有限重试、取消、重启和人工确认语义。
- 定义外部 Skill 的隔离导入、自动预检、人员审核、版本锁定、权限代理、撤销和红队验收边界。
- 给出与现有 Electron、Vue、TypeScript 和 Agent Harness 衔接的分阶段实施建议。
- 补充 OpenAI-compatible、Anthropic、Gemini 三类 BYOK 模型适配器、角色绑定、能力探测和禁止静默跨供应商回退的设计。
- 补充独立项目文件夹、纯文本选区 AI、快速/标准/深度生成模式、TXT/Markdown/DOCX 导出和 Windows 测试安装包决策。
- 新增一份决策完备的全阶段开发计划，逐阶段定义交付物、接口、依赖、测试和退出标准。
- 同步本日期目录 README，并记录实际结果与验证结果。

### 明确不包含

- 不修改任何运行时代码、配置、依赖或数据库。
- 不接入真实模型，不创建 API 密钥或模型供应商配置。
- 不实现小说 CRUD、正文编辑器、SQLite 存储或 Skill 运行时。
- 不安装或执行任何来自 GitHub 的第三方 Skill。
- 不修改或提交工作区中已有的 Electron smoke、CI 和其他用户变更。

## 实施步骤

1. 汇总已确认的目标、题材、输入材料、人工确认边界和质量要求。
2. 编写总体架构、Agent 职责、两条核心工作流和小说圣经设计。
3. 编写外部 Skill 的人员审核与底层隔离设计，并区分首版声明式 Skill 与后续可执行 Skill。
4. 补充异常处理、安全、隐私、测试、评测和首版验收标准。
5. 对设计文档执行占位符、矛盾、范围和歧义自检并修正。
6. 调研并锁定多供应商模型、纯文本编辑器、本地数据库与 Windows 安装包的技术边界。
7. 编写全阶段开发计划，明确公共契约、阶段依赖、验收场景和最终安装闭环。
8. 更新本计划的实际结果和验证结果，同步两个日期目录及上级 README。
9. 运行 `npm run check:readmes` 和文档检查，确认本任务差异不覆盖工作区已有用户变更。
