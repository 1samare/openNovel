# 开发进度清单与阶段入口约束计划

## 修改目标

建立一个位于仓库根目录、可供人类和 Agent 快速接手的开发进度清单，并通过根级协作约束要求每次阶段开发前读取清单、核对工作区与分支、登记任务，结束或暂停时写回可执行的交接信息。

## 修改范围与明确不包含的内容

### 修改范围

- 新增根目录 `DEVELOPMENT_PROGRESS.md`，记录总体阶段、活动工作区、分支、计划、状态、最近验证、阻塞项和下一步。
- 登记当前主工作区和 Harness worktree 的可发现 Git 信息，不推断另一工作区未读取的任务进度。
- 修改 `AGENTS.md`，增加开发任务进入、执行中更新和离开时交接的强制流程。
- 更新根目录与 docs 相关 README，说明进度清单的用途和维护方式。
- 运行 README、文档、空白与清单内容检查并回填实际结果。

### 明确不包含

- 不修改应用运行时代码、测试逻辑、依赖、构建配置或数据库。
- 不创建、切换、删除或合并 Git 分支和 worktree。
- 不提交、暂存或清理工作区现有修改。
- 不引入自动同步服务、GitHub Issues 或新的检查脚本。
- 不替其他工作区推断完成状态；没有验证依据的状态标记为“需核实”。

## 实施步骤

1. 读取当前 Git 根目录、分支、HEAD、worktree 列表和工作区状态。
2. 定义进度状态、活动任务表、阶段总览和单次交接记录模板。
3. 新增根目录进度清单，并用已验证信息初始化当前工作区记录。
4. 在 `AGENTS.md` 中加入阶段任务开始前读取、任务期间更新和离开前交接的强制规则。
5. 同步根目录及 docs README，明确清单是开发交接入口但不替代阶段修改计划。
6. 执行占位符、README 契约、文档测试、Git 空白和差异范围检查。
7. 回填实际结果和验证结果。

## 验证方式与通过标准

- `DEVELOPMENT_PROGRESS.md` 明确列出两个当前 worktree 的绝对路径、分支与 HEAD。
- 阶段 0–8 的状态和下一步可在单页内定位。
- `AGENTS.md` 明确要求阶段开发开始前先读取清单并核对 Git 上下文。
- 任务暂停、切换工作区或完成时必须记录最近验证、下一步和未提交变更归属。
- 清单明确自己不替代 `docs/YYYY-MM-DD/*计划.md`，且不得伪造未验证状态。
- `npm.cmd run check:readmes`、文档测试和 `git diff --check` 通过。
- 最终差异不包含应用代码、依赖、分支或 worktree 操作。
