# 阶段 1 独立项目与本地数据库实施计划

> **供 Agent 实施者使用：** 必须使用 `superpowers:executing-plans` 逐项执行；功能和缺陷修复使用 `superpowers:test-driven-development`，完成声明前使用 `superpowers:verification-before-completion`。步骤使用复选框跟踪。

**目标：** 让用户可以通过系统目录选择器新建、打开、关闭、重命名和备份独立小说项目，并在重启后从应用级最近项目列表重新打开或恢复项目。

**架构：** 共享层定义固定项目契约；`src/novel/` 负责路径、manifest、锁、SQLite Worker、项目仓储和生命周期；主进程只组合系统对话框、运行时与受限 IPC；preload 只暴露命名 `projects` API；Vue 项目中心消费该 API。项目数据库和应用级 `control.sqlite3` 都通过串行 Worker RPC 访问，渲染进程不接触路径、数据库或任意文件 API。

**技术栈：** Electron 43、Vue 3、TypeScript 6、Electron 内置 Node 24 `node:sqlite`、Node Worker Threads、Node Test Runner、Vitest、Vue Test Utils、happy-dom。

## 全局约束

- 只完成阶段 1；不增加章节、编辑器、导入导出、模型、Agent 小说工作流或 Skill 能力。
- 不新增 npm 依赖；使用 Electron 内置 Node 的 `node:sqlite`、`worker_threads` 与文件系统 API。
- 每部小说使用独立目录，固定包含 `open-novel.json`、`project.sqlite3`、`attachments/`、`backups/`、`exports/`。
- manifest 必须原子写入且严格校验；数据库启用 foreign keys、WAL、`busy_timeout` 与 `user_version` 迁移。
- 项目锁拒绝并发写入；陈旧锁只能在调用方明确确认后恢复。
- renderer 不获得任意路径、文件、SQLite、通用 IPC 或 Node/Electron 能力；所有 IPC 复用现有 sender 白名单并做运行时参数校验。
- 删除最近项目记录不删除磁盘项目；真实删除项目不纳入 V1。
- 新增目录先有 README；修改维护目录文件时同步更新同目录 README；不读取、修改或暂存用户既有 `.superpowers/`。

**接口：**

- `ProjectService.create({ root, title })` 创建目录、manifest、数据库、基础项目记录、子目录和锁；任何失败逆序清理本次创建的资源。
- `open({ root, recoverStaleLock })` 验证 manifest、锁和数据库健康后返回活动项目摘要。
- `rename(title)` 在同一受控操作中更新数据库项目名与原子 manifest；失败时不得留下不一致成功状态。
- `backup(destinationRoot)` 写临时备份、验证 manifest 和 SQLite `quick_check` 后原子改名。

- 备份和恢复源/目标必须拒绝相互包含的递归路径；迁移前备份必须证明可读取/可还原，而非只证明文件存在。
