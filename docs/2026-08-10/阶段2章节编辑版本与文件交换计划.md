- 编辑恢复：800ms 防抖和切章/关闭/退出 flush 测试通过；保存失败时内存稿与错误状态持续存在。
- 导入：预览和事务实际写入的标题、内容、字数完全一致；TXT/Markdown/paste 三来源通过。
- 导出：TXT、Markdown、DOCX 来自同一快照，卷章顺序、标题、正文与共享字符计数一致，中文编码可读。
- 备份：最终文件以 `.opennovel.zip` 结尾，manifest、SQLite quick check 和所有 SHA-256 通过，排除 API Key 与非项目数据。
- 安全：固定 IPC、sender/参数/响应守卫和错误脱敏测试通过，renderer 无任意文件或 SQL 能力。
- 全门禁：README、严格类型、Node、UI、生产构建、Electron smoke、acceptance 和 Git 空白检查全部退出 0。

## 设计路径比较与采用结论

1. **采用：领域服务 + 固定 IPC + CodeMirror 组件的完整纵向切片。** 与既有阶段 1 Worker/Runtime/Preload 分层一致，能把数据库事务、文件权限和 UI 状态分别测试，成本最高但唯一完整满足阶段退出标准。
2. renderer 本地维护章节正文、项目 API 只存最终文本：实现较快，但无法可靠保证退出 flush、不可变版本和数据库事务，不采用。
3. 使用 `<textarea>` 暂代 CodeMirror、后续替换：依赖较少，但直接违背阶段 2 的中文输入、搜索替换、选区和只读候选要求，不采用。
